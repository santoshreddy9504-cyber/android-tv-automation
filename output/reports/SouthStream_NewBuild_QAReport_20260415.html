BUG #1 — BLOCKER
App Crashes on Content Language Change
Blocker

Settings → Content Language

16:48:51 (2m 7s into session)

100% reproducible — every time language is changed

302.7MB (rising from 250MB in <2 min)

  • 1Open SouthStream on Fire TV
  • 2Navigate to Settings (left sidebar)
  • 3Open Content Language settings
  • 4Select any different language
  • 5App crashes silently — returns to Fire TV home screen

Language changes successfully, content reloads in selected language, user stays in app

App crashes silently with no error message. Returns to Fire TV home. All unsaved state lost.

Root Cause Analysis

When user changes content language, the app navigates away from the Language settings screen. A Reanimated animation was still running on the settings screen view (tag 2569). When the screen unmounts during navigation, the view is destroyed — but the Reanimated thread continues trying to update it → FATAL EXCEPTION.

Additionally: immediately before the crash, content tried to reload with the new language but returned undefined data — images loaded from https://undefined/undefined — same broken data pipeline as the series episodes bug.

BUG #2 — HIGH
Memory Leak — RAM stays above 400MB for 20+ minutes
High

General navigation / content browsing

16:57 → 17:15 = 18 continuous minutes

482.8MB at 17:13:04

~230–260MB at startup

Memory stays stable during browsing. GC collects unused objects regularly. RAM stays below 300MB.

RAM climbs steadily during navigation. Stays above 400MB for 18+ minutes without releasing. Peak 482MB — just below the crash threshold seen on April 14 (483MB).

Root Cause Analysis

Screen components and event listeners are not being properly cleaned up when navigating between screens. Each navigation adds memory that is never released. The GC eventually forces a cleanup (seen at 17:15 — drops from 475MB to 407MB) but this is too late and too infrequent. Confirmed memory leak. If session continues beyond 35–40 minutes, another crash is expected.

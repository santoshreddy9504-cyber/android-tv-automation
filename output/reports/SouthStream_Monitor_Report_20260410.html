Root Cause Analysis
All 4 crashes share one single root cause. This is a code bug, not an infrastructure issue.
FieldDetail
Exceptioncom.facebook.react.common.JavascriptException
ErrorInvariant Violation: scrollToIndex should be used in conjunction with getItemLayout or onScrollToIndexFailed
Threadmqt_native_modules (React Native native module queue)
EngineHermes JS engine
Call StackonFocus → scrollToLocation → scrollToIndex → invariant (throws)
TriggerD-pad navigation moves focus to a content item that is off-screen in a FlatList. The app tries to scroll to that item's index, but without getItemLayout prop, React Native cannot calculate the position — so it throws a fatal invariant violation.
Affected ComponentA FlatList or SectionList content grid (likely the main content browse row)
Fix RequiredAdd onScrollToIndexFailed handler to the FlatList — or — provide getItemLayout prop with fixed item dimensions
How to Fix (React Native)
Option A — Add onScrollToIndexFailed (easiest fix, no layout calculation needed):
<FlatList
  data={items}
  onScrollToIndexFailed={(info) => {
    const wait = new Promise(resolve => setTimeout(resolve, 500));
    wait.then(() => {
      flatListRef.current?.scrollToIndex({
        index: info.index,
        animated: true
      });
    });
  }}
/>
Option B — Add getItemLayout (better performance, requires fixed item height):
getItemLayout={(data, index) => ({
  length: ITEM_HEIGHT,   // fixed height of each row/card
  offset: ITEM_HEIGHT * index,
  index,
})}
